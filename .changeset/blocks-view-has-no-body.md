A view has no body (D-032). A view is `function* () { return <…/>; }`: every read is a hole (a `yield*` in a JSX position, or in `h` / `html` a source or a bare `function*` hole), and structure comes from flow controls, which take sources directly. Whole-view re-rendering is removed. A view that read at its top level used to be detected on its first run, re-rendered as a whole in a memo from then on, and warned about (`VIEW_READS_OUTSIDE_JSX`). Such a read is now the development error `[READ_IN_VIEW] <Component>: read outside a JSX position`, naming the component, or `row <name>` for a row's view. The error fires on the server as well as the client. Reads that come through `perform` (JSX positions) and reads by computations the view's run creates (a flow control reading its props, a hole's first pass) stay the holes' own. Production builds no longer check: a view runs once, as the VIEW host. `renderView(view, name)` takes the name it reports.

In the no-JSX flavor the type now holds the rule. `HViewOp` is `never`: an `h` / `html` view yields nothing, not even a child view (a child is `h(Child, props)`), and its pending and failures are its output's (`[HVIEW_READ] a no-JSX view does not read`). A JSX view cannot be held to it by its type. TypeScript types a `yield*` in JSX (a hole, after the transform) and one in a statement alike, and the former is how a JSX view's coloring is its holes', so `ViewOp` stays `Read | ChildView` and the runtime and the lint hold the rule there.

`@solidjs/eslint-plugin-blocks`: `no-read-in-view-body` (in `recommended`) replaces `no-read-outside-hole`. It reports any `yield*` in a view outside a JSX expression or attribute: a read, a branch on one, or a top-level `yield* Child(…)`. A bare `function*` hole's reads are its own. Views and rows are recognized in more places: a setup returning one of several views (a conditional return), a flow control's `children:` / `fallback:` row in the call form, and a row bound to a `const` in a setup, so `h`-flavor rows' views are now checked. Its first run found no site in any of the twelve twins. Two room-twin views that aliased a path in their bodies (no read) now do it in their setups, and the twins' behavior suites drop their assertion that the old warning never fired.
