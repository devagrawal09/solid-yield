Typed failures v2 for `@solidjs/blocks`. `attempt(fn, onError)` replaces `attempt(fn, ...Errors)`: the handler turns whatever `fn` throws, or its promise rejects with, into the error object the block fails with, and the handler's return type is the failure's color (each error class needs a member of its own, e.g. `readonly kind = "not-found"`, for TypeScript to tell two apart). When `fn` returns a stream (or a promise of one) the attempt gives the stream back with its failures mapped through `onError` as they arrive. A `$memo`, `$projection`, `$optimisticStore` or `$dynamic` body that returns a raw promise or stream is now a type error (`return yield* attempt(() => it, onError)`), so a memo no longer fails with `unknown`. `<Errored catch={[NotFound]}>` handles only the listed classes, removes them from its children's failures and rethrows any other error to the boundary above. New `until(source, onError, options)` is an async `attempt` over Solid's `until`.

`$event` is now a Solid `action`: each call is one transaction (writes are held until it settles, optimistic writes show at once), and an async `attempt` re-enters the transaction when its promise settles. It takes any arguments and returns an `EventCall`, a promise of the body's result that is also an operation: `yield* save(x)` waits for the call, returns its result, throws its failure at the `yield*` and carries its colors into the caller's type, while `yield* start(save(x))` runs it without waiting. A failure goes to whoever handles the returned promise; one nobody handles goes to the nearest `Errored` (the promise resolves `undefined`), or the promise rejects when there is no boundary. A read inside an event that hits a pending source waits for its data instead of throwing. `EventHandler<Args, E, R, P, A>` carries two colors read off the body: `ReadsPendingOf` (it reads pending data) and `WaitsOf` (it does async work of its own). An `$effect` may delegate only to a call that has neither. New exported types: `EventCall`, `EventCallOp`, `ReadsPendingOf`, `WaitsOf`. Setters are now lazy: a setter call returns a receipt, and the write happens only at `yield* setX(v)`.

New creators wrap Solid 2 primitives with block bodies: `$optimistic`, `$optimisticStore` (plain, or derived from a body, with `seedLoadingValue`), `$projection` and `$dynamic` (Solid's `dynamic()` with a block body). `refresh(target)` is a write. Block code now reads and writes only with `yield*`, so these escape hatches leave the public surface: `read()`, `paths()`, `accessor()`, `$flush` with its `Flush` op type, and `readStore`'s overload for a foreign `Store`.

`@solidjs/eslint-plugin-blocks`: `no-unyielded-write` replaces `no-write-in-reactive`. It reports a block setter (including `$optimistic` / `$optimisticStore` setters) called without `yield*`. With type information (`parserOptions.projectService`) it also reports an `EventCall` that is neither delegated to, started nor stored, and any other block operation the code discards. New `no-foreign-reactive` reports value imports of reactive primitives from `solid-js`, `@solidjs/signals`, `@solidjs/router` and `@solidjs/web`, and names the block replacement (the table is exported as `FOREIGN_REACTIVE`). The example twins move to these APIs: attempt handlers with per-app error classes (in `errors.ts` modules where an app has several), `$event` in place of `action`, and no reactive imports from plain Solid or the router.
