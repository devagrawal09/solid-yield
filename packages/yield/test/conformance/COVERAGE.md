## Library route vs compiler route (server output)

`routes.spec.ts` compares `server/library`'s output with the compiler route's (`__artifacts__/compiler-route/`, the fork's `server/yield-compiled`, frozen). Every difference is a finding, recorded in DECISIONS.md:

- **yield-row-list** (D-069 F6): The markup is the same; the hydration keys are not. The compiler route makes each `component` view and row view a hydration id scope (`blockScope`: one slot reserved where the routine is created, its content numbered inside: `00`, `01000`, `01100`); the library route has Solid's owner ids, where each hole and each flow control called in one is an owner (`0`, `1000`, `1010`). Each route hydrates its own markup with every node kept, and the two are not interchangeable: the library client given the compiler route's markup misses every key, the root's included, and the page stays inert (hydrate-self-test.spec.ts; the reverse needs the yield compiler, which is not here). `<!--!$-->` between rows is in the compiler route's output only; rc.13's own reference does not emit it either (the fork's Solid did), so it is Solid's drift, not the route's.

## Semantic areas

- **yield-counter**: component setup runs once; memo in setup; view reads; event reads and writes
- **yield-effect**: effect reads and writes; effect cleanup per run and on dispose; branch reads in an effect; effect split (compute / effect halves)
- **yield-props-child**: props forwarded as a source; child setup runs once; parent re-render does not re-create the child
- **yield-async-resolve**: async memo under Loading; Loading / Errored call forms; boundary nesting
- **yield-async-reject**: async failure reaches Errored through Loading; typed failure
- **yield-async-event**: event that waits (`yield* attempt(() => promise, onError)`); write after the wait; context read through a helper generator (`yield* Ctx`, D-036)
- **yield-row-list**: row routine: setup once per row, under the row's owner; row routine: each row's own state (a handler in the row writes it); row routine: rows added, removed and reordered keep or drop their state; row routine: $cleanup when the row is removed and on dispose
- **yield-row-recursive**: named row routine declared in a setup; recursive row routine (renders itself for its children); per-instance state at every depth
- **yield-row-keyed-store**: row routine reading a store map by its own key; a handler in the row writing the store at its own key
- **async-flights**: async pending; async resolve; superseded stale flight; async reject → boundary; continuation ownership; loading/error markers
- **async-disposal**: disposal before settlement; no commit after disposal
- **async-event**: async event pending/resolve; async event reject → boundary of the creating owner; writes before and after an event wait
- **async-hydration**: SSR async resolve + Loading markers; hydration reuses serialized async results (no duplicate authoritative work); post-hydration async update
- **loading-fallback-hydration**: a call-form Loading whose content the server renders in place hydrates without building its fallback (D-092)
- **error-routing**: synchronous throw; typed failure (raise); untyped failure (attempt); local recovery (an absorbing attempt); error-boundary routing and reset; a bound event's failure routes to the bind site (D-085)

## Not ported

- **yield-context**: moot under D-036: `yield* Ctx` on a library context is the one way to read one, so there is no second form to pin; yield-async-event still reads a context, through a helper generator
- **memo-effect-order, dynamic-subscriptions, owned-children, owner-routing, event-reads-writes, store-paths, store-dynamic-index, prop-paths, jsx-block, error-markers**: written for the `$`-block proposal (a reference and a `$` source, no library source); a library source for each is a candidate for a later port
- **tier-toggle, tier-two-cells, tier-shared, tier-diamond, islands-***: pin the compiler's island activation and runtime tiers, which the library does not have (yield-library.md §7)
- `*/compiled, */fused, */runtime` — the `$`-block proposal's driver, lowering and host fusion: the `$` dialect is not this library's (D-013); those scenarios stayed in the fork
- `*/yield-compiled` — yield components through a yield compiler: no yield compiler here (D-043); its server output is kept as `__artifacts__/compiler-route/` and compared with the library route in routes.spec.ts
- `client/yield-uncompiled` — yield components with a generic JSX transform: superseded: the library route runs the yield rule, so every JSX hole is its own computation (D-003)
- `islands, tiers` — island activation and runtime tiers (islands.spec.ts, tiers.spec.ts): compiler features the library does not have (yield-library.md §7: no islands, no runtime tiers)
